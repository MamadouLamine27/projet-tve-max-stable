📘 Git · guide doux pour débutant

Pas de panique : Git est un outil pour sauvegarder ton code, voyager dans le temps et travailler en équipe.
Voici les seules commandes dont tu as besoin pour démarrer sereinement.

🧠 L'analogie qui change tout

Imagine que ton projet est un jeu vidéo :
  • 📁 Working directory → là où tu joues (tes modifications en cours)
  • 📦 Index (stage) → zone d’attente avant de sauvegarder
  • 💾 Commit → une sauvegarde définitive (avec un message)
  • 🌍 Remote (GitHub) → le cloud pour partager ou sauvegarder à distance
💡 Astuce : un commit, c’est comme une photo de ton projet à un instant T. Tu pourras toujours revenir en arrière.

🔧 1. Installation & identité à faire une fois

Avant tout, Git doit savoir qui tu es (ton nom et email apparaîtront dans l’historique).
git config --global user.name "Ton Prénom Nom"
git config --global user.email "ton.email@example.com"
✅ Vérifie ta config : git config --list

📁 2. Démarrer un projet (2 façons)

OPTION A Créer un dépôt local depuis zéro
cd mon-dossier-projet
git init
OPTION B Récupérer un projet déjà sur GitHub
git clone https://github.com/utilisateur/nom-du-repo.git
🔁 git clone télécharge tout l’historique + crée automatiquement un lien vers le dépôt distant.

🔄 3. Le cycle quotidien (sauvegarder son travail)

✏️ Modifier des fichiers
➕ git add
💾 git commit
📤 git push
👉 Voir l’état des fichiers (modifiés, ajoutés, etc.)
git status
👉 Ajouter un fichier à la zone de préparation (stage)
git add monfichier.js # un seul fichier
git add . # tous les fichiers modifiés
👉 Enregistrer la version (commit) – avec un message clair
git commit -m "fix: correction du calcul de moyenne"
👉 Voir l’historique des sauvegardes
git log --oneline # version condensée, chaque commit a un identifiant
📝 Un bon message de commit : commence par un verbe (ajoute, corrige, améliore) et explique le POURQUOI.

☁️ 4. Relier ton projet à GitHub (sauvegarde cloud)

Après avoir créé un dépôt vide sur GitHub (sans README), lie-le à ton projet local :
git remote add origin https://github.com/ton-compte/nom-projet.git
git branch -M main
git push -u origin main
👉 Envoyer tes commits sur GitHub (après avoir fait git commit)
git push
👉 Récupérer les derniers changements depuis GitHub (important avant de commencer à coder)
git pull
🌟 git pull = télécharge les nouveautés + les fusionne avec ton travail local. Fais-le souvent pour éviter les conflits.

🌿 5. Les branches : l’arme secrète

Une branche, c’est une version parallèle de ton projet. Tu peux expérimenter sans casser la version principale (main).
git branch ma-fonctionnalité # crée une branche
git checkout ma-fonctionnalité # bascule sur cette branche
# (ou en une seule commande : git checkout -b ma-fonctionnalité)
👉 Fusionner une branche dans main (une fois que la fonctionnalité est prête)
git checkout main
git merge ma-fonctionnalité
🧪 Bon réflexe : crée toujours une branche pour chaque nouvelle fonctionnalité ou correction. Ta branche main restera propre.

⚠️ 6. Que faire en cas de conflit ?

Un conflit arrive quand deux personnes modifient la même ligne d’un fichier. Pas de panique, Git te guide.
# après un git pull ou git merge, Git te dit : CONFLIT
# Ouvre le fichier concerné, cherche les marqueurs :
<<<<<<< HEAD
ton code actuel
=======
code de l'autre branche
>>>>>>>
# Corrige manuellement (garde ce qui doit rester) puis :
git add fichier_conflit.js
git commit -m "résolution conflit"
🛠️ Petit conseil : avant de git pull, assure-toi d’avoir commité ton travail. Utilise git status pour voir où tu en es.

⏪ 7. Annuler des modifications (sans peur)

👉 Annuler les modifications non encore ajoutées (dans le working directory)
git restore monfichier.js
👉 Désajouter un fichier du stage (git add par erreur)
git restore --staged monfichier.js
👉 Revenir au dernier commit (perdre toutes les modifications locales)
git reset --hard HEAD
⚠️ git reset --hard est définitif. Utilise-le seulement si tu es sûr de vouloir tout jeter. Sinon, préfère git stash (range temporairement ton travail).

🧹 8. Ranger temporairement son travail : git stash

Tu es en plein milieu d’une modification, mais tu dois changer de branche ou tirer les dernières mises à jour ?
git stash met de côté tes changements en cours (proprement).
git stash # range les modifications non commitées
git stash pop # les réapplique et supprime le stash
📦 Utile quand tu veux git pull sans perdre ton travail en cours.

🔀 9. Pull Requests : le cœur du travail en équipe GitHub

En équipe, on ne pousse (presque) jamais directement sur main. À la place, on propose ses changements via une Pull Request (PR) : une demande de fusion que les autres peuvent relire, commenter et approuver avant qu’elle rejoigne le projet.
🌿 Branche
💾 Commits
📤 Push branche
🔀 Ouvrir la PR
👀 Review
✅ Merge
👉 1. Crée ta branche et pousse-la sur GitHub
git checkout -b ajout-page-contact
# ... tu codes ...
git add .
git commit -m "feat: ajoute la page de contact"
git push -u origin ajout-page-contact
👉 2. Ouvre la Pull Request — après ton push, GitHub affiche un bouton Compare & pull request. Clique dessus, écris un titre clair + une description (le POURQUOI et comment tester), puis crée la PR.
👉 3. La review — tes collègues lisent le code, laissent des commentaires ligne par ligne, et choisissent Approve (c’est bon) ou Request changes (à corriger). Tu ajustes en poussant de nouveaux commits sur la même branche : la PR se met à jour toute seule.
👉 4. Le merge — une fois approuvée, on clique sur Merge pull request. Ta branche peut ensuite être supprimée sans risque.
🔗 Astuce : écris Fixes #42 dans la description de la PR pour fermer automatiquement l’issue n°42 dès que la PR est fusionnée.

🍴 10. Le fork : contribuer au projet des autres open source

Tu veux participer à un projet où tu n’as pas les droits d’écriture (un projet open source, par exemple) ? Tu fais un fork : une copie personnelle du dépôt sur ton propre compte GitHub.
ÉTAPE 1 Clique sur Fork sur GitHub, puis clone ta copie :
git clone https://github.com/ton-compte/le-projet.git
cd le-projet
ÉTAPE 2 Ajoute le dépôt d’origine comme upstream pour rester à jour :
git remote add upstream https://github.com/projet-original/le-projet.git
git fetch upstream
git merge upstream/main # récupère les nouveautés du projet original
ÉTAPE 3 Crée ta branche, pousse-la sur ton fork, puis ouvre une Pull Request vers le projet original. Les mainteneurs la relisent et décident de l’intégrer.
🧭 origin = ton fork (tu écris dessus). upstream = le projet original (tu lis dessus). Vérifie avec git remote -v.

🗂️ 11. Diriger un projet : Issues & Kanban sur GitHub

Git gère le code, mais GitHub gère l’organisation. Ces outils vivent dans l’interface web (aucune commande à taper) et c’est là que se pilote un projet en équipe.
🐛 Les Issues — une issue = une tâche, un bug ou une idée. Chacune a un titre, une description, et peut recevoir :
  • 🏷️ des labels (bug, enhancement, good first issue)
  • 👤 un·e assigné·e (la personne qui s’en occupe)
  • 🎯 un milestone (regroupe des issues vers un objectif, ex : « version 1.0 »)
📋 Le tableau Projects — un Kanban intégré à GitHub. Tu déplaces tes issues et PR d’une colonne à l’autre :
📥 To do
🔨 In progress
👀 In review
✅ Done
🔗 Relie le code au suivi : dans un commit ou une PR, écris closes #12 et l’issue n°12 se ferme automatiquement au merge. Toute l’équipe voit qui fait quoi et où en est le projet.

🧭 12. Bonnes pratiques pour mener une équipe

🔒 Protège la branche main — dans les réglages GitHub (Settings → Branches), exige une PR + au moins une review avant tout merge sur main. Ainsi personne ne casse la version principale par accident.
✍️ Adopte une convention de commit — des messages lisibles par toute l’équipe :
feat: nouvelle fonctionnalité
fix: correction de bug
docs: documentation
refactor: réécriture sans changer le comportement
test: ajout ou correction de tests
🙈 Crée un fichier .gitignore — pour ne JAMAIS envoyer les fichiers inutiles ou secrets sur GitHub :
node_modules/
.env # ⚠️ ne commit jamais tes mots de passe / clés API
*.log
dist/
🏷️ Marque les versions avec des tags — pour livrer des versions officielles (releases) :
git tag v1.0.0
git push origin v1.0.0
📁 Un projet bien dirigé a souvent un README.md (présentation), un CONTRIBUTING.md (règles pour contribuer) et un CODEOWNERS (qui relit quoi). Ça guide les nouveaux arrivants tout seul.

📋 Mémo visuel des commandes quotidiennes

git status → état des fichiers
git add . → préparer tous les fichiers
git commit -m "msg" → sauvegarder
git log --oneline → historique
git push → envoyer sur GitHub
git pull → récupérer les nouveautés
git branch → lister les branches
git checkout -b nom → créer + basculer
git merge branche → fusionner
git restore fichier → annuler modifs
git stash / pop → ranger temporairement
git remote -v → voir l’URL GitHub liée
git push -u origin branche → publier une branche
git fetch → récupérer sans fusionner
git tag v1.0.0 → marquer une version
🎯 La règle d’or : commit souvent, avec des messages clairs, et pull avant de commencer à coder.

🚀 Exemple concret : une journée de travail avec Git

  1. git pull → je récupère le dernier code de l’équipe
  2. git checkout -b nouvelle-fonction → je crée une branche pour ma fonction
  3. Je code, je sauvegarde : git add . puis git commit -m "ajout du formulaire"
  4. Je recommence (ajout/commit) plusieurs fois
  5. Quand c’est prêt : git push -u origin nouvelle-fonction → je publie ma branche
  6. J’ouvre une Pull Request sur GitHub, un·e collègue relit, puis on fusionne dans main
🌈 Ne pas avoir peur : tant que tu as commité, tu ne perds rien. Git garde chaque version.

💬 Erreurs débutantes (et solutions)

  • ❌ "fatal: not a git repository" → tu n’as pas fait git init ou tu n’es pas dans le bon dossier.
  • ❌ "Please tell me who you are" → oubli de git config --global user.name/email
  • ❌ "rejected" lors du push → quelqu’un a poussé avant toi. Fais git pull, règle les conflits, puis repush.
  • ❌ "detached HEAD" → tu es sur un ancien commit. Tape git checkout main pour revenir.
📚 Besoin d’aide sur une commande ? git --help ou git add --help affiche la documentation.
⚡ Guide pensée pour les vrais débutants – utilise git status aussi souvent que tu respires, ça t’évitera 90% des surprises.
